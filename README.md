## 快速开始

```bash
pnpm install
pnpm start          # 构建 + 启动（开发态）
pnpm typecheck      # 两端 tsc
pnpm test           # 103 条纯函数断言（标题识别 / 围栏 / 表格 / 对齐 / 快捷键 / 无损边界 / 数据安全 P0）
pnpm verify         # 245 篇旧笔记逐字节往返校验 + 裂图基线比对
pnpm pack           # 打包 → release/简牍-<version>-portable.exe（推荐）
pnpm dist           # 同上，但直接输出到 release/（本机守卫会拦，见下）
```

> **启动必须带 `--user-data-dir`**，`scripts/run.mjs` 已经处理。原因见下。

## 三条不能破的线

1. **数据不丢** — 写盘走 tmp + fsync + rename；失败必弹错；单实例锁防止两个编辑器互相覆盖。
2. **中文输入** — 组字期间不重排、不丢字、光标不跳。
3. **无损** — 纯文本是唯一真源。渲染层只读叠加，**永不回写美化后的文本**；不认识的语法原样保留；不统一换行符。

`pnpm verify` 就是这条红线的守门人：240 篇旧笔记 `decode → encode` 后必须**逐字节相等**（CRLF/LF、BOM、末尾无换行全藏在这个断言里），且裂图数不超过 94 的已测基线。非 UTF-8 的篇目**不参与**往返比对（坏字节解成 `�` 再编码回不去，比了必然红），会单独列一区打印——它们在编辑器里是只读的，你得知道有这几篇。

`pnpm test` 守的是另一半。`verify` 只比字节，它看不见"渲染成什么样"——标题该不该认（含列表项里的 `- ## x`）、围栏什么时候闭合、表格怎么切列、空格能不能当快捷键，这些改坏了字节一个不差，只会在界面上错位。所以 `scripts/test-units.mjs` 把踩过的边界逐条钉成断言（**103 条**，零新增依赖，走 `node:test`；其中 8 条是 `writeNote` 的落盘集成测试，用 `os.tmpdir()` 建临时目录跑完即删）。

> 为什么数据安全那几条必须落盘才测得出来：往返校验比的是「我们的解码器 vs 我们的编码器」，两边一起错就永远是绿的。那 8 条比的是另一件事——**面对磁盘上别的程序留下的真实字节，我们有没有动手**。其中最刁的一条是「快路径只认主进程亲自验过的文件」：渲染层送回来的 `expectMtimeMs`/`expectSize` 就是它自己从 `readNote` 拿到的，一个从没被我们读过的 GBK 文件，指纹照样百分之百命中。

### 主题兼容的关键

Typora 主题写的是 `#write h1`、`.md-fences`，而 CM6 的行是 `.cm-line`。两边靠三件事对上：

1. **DOM 尽量像 Typora**：外层 `.jd-content`（对应 Typora 的 `content` 元素）包 `#write`。
2. **选择器映射**：翻译时用 `postcss` + `postcss-selector-parser` 把主题选择器改写成我们的语义 class（见 `src/theme/mapping.json`）。这份 JSON 是**唯一真相源**——代码里的兜底表由构建期内联它生成，不另抄一份。
3. **代码 token 配色**：主题里写的是 CodeMirror 5 的 `.cm-s-inner .cm-keyword`。翻译时剥掉作用域类、把 `.cm-*` 改名成 CM6 `classHighlighter` 输出的 `.tok-*`（`tok-keyword`/`tok-string`/`tok-comment`…），主题自带的高亮配色就原样生效。

**为什么运行时翻译而不是把改好的 CSS 存进项目**：换主题、改主题随时发生。热重载让你在 Typora 里改一行、这边 500ms 内跟着变。

### 内置的两档兜底

主题下拉最前面两项**不是文件**，它们不走翻译管线：

- **（内置）** —— Typora 默认浅色的等价物（白底 `#fff` / 正文 `#333`）
- **（内置 · 深色）** —— 同一套骨架，只把底色、正文色、代码块底色换掉，
  由 `theme-base.css` 的 `html[data-builtin='dark']` 一组变量接管（`#1e1f22` / `#ced2d6`）

两个档位在 `ThemeCompatReport` 里都没有可报告的内容 —— 报告面板会提示「当前是内置样式」。

> 外壳（侧栏 / 状态栏 / 原生标题栏）始终是深色。所以「内置 · 深色」和外壳是协调的，
> 「内置」则是白纸配深边框 —— 那是刻意保留的对照，需要长时间深色阅读时选前者。

### 主题兼容度报告（`Ctrl+Alt+R`）

菜单 **设置 → 主题兼容度报告**。翻译管线的每一处取舍都在这里：

- **8 个计数**：应用 / 丢弃规则、`@font-face`、`@keyframes`、内联 `@import`、`url()` 重写、内联文件数、输出行数
- **被丢弃的规则**：通常是 Typora 应用外壳（侧栏 / 菜单 / 导出页），我们没有对应 DOM，留着也是永不生效的死规则
- **被改名的选择器**：左边主题里写的、右边落到我们 DOM 上的 —— 想知道「`#write h1` 最后变成了什么」就看这里
- **警告**：不影响加载，但解释了「某处为什么和 Typora 不一样」（比如 `?t=` 缓存串被丢弃、`inline-block` 标题被改成 `block + fit-content`）

底部「复制报告」导出纯文本，贴这一段比截图更容易排查。

> 选「（内置）」时打开会提示没有可报告的主题。

### CSS 五层顺序（是契约，别调）

```
style.css          外壳
theme-base.css     Typora 排版骨架（我们自己补的，主题只写差异）
<jd-typora-theme>  翻译后的主题
<jd-theme-fix>     把「一串 .cm-line」拼回一个代码块/表格框
<jd-shell-guard>   防止主题把侧栏/状态栏刷坏
```

后三层由 `renderer/theme.ts` 在**运行时** append 到 `<head>` 末尾。
**不要用 `@layer`**：CM6 运行时注入的样式是未分层的，未分层永远压过分层，一分层反而被反噬。

`theme-fix.css` 里还压了三条**外壳级强制项**（不属于主题表达范围，对所有主题一致）：

- 正文区 `max-width: 90%` —— 各主题自带的阅读宽度（80em / 860px）在宽屏上留白过多。
  **限宽只能挂在 `.cm-editor` 上**：`#write` 自己是滚动容器，给它限宽会把滚动条一起拽到 90% 那条线上（详见「已知的坑」）。
  同时 `#write` 的**左右 padding 必须归零**，否则 40px 内边距会被 90% 再切一刀，
  正文实际只剩 84.2%；内边距改由 `.cm-editor` 提供，取值走 `--jd-write-pad`（默认 30px，主题可覆盖）
- 所有行级元素 `margin: 0 !important` —— CM6 的行块测不到 margin，详见「已知的坑」里那条
- 滚动条自绘 —— 颜色由 `color-mix(in srgb, currentColor 22%, transparent)` 从主题正文色派生，
  深浅主题自动适配，不用维护色表。主题自己写了 `--scrollbar-color` + `!important` 时以主题为准

## 原生标题栏跟随主题明暗

顶部那一条是 Windows 画的（DWM），渲染层的 CSS 碰不到。所以主题切换后由渲染层算一次
body 背景的**感知亮度**（ITU-R BT.601 加权，别用三通道平均值 —— 深蓝深红会判错），
通过 `app:titlebar-theme` 交给主进程设 `nativeTheme.themeSource`，Windows 才会把标题栏
（含右上角三个按钮）切成深色或浅色。

只能表达「深 / 浅」两档。想精确到主题那个具体色值（比如 `#262626`）必须改成无边框自绘标题栏。

## 偏好设置（4.10.0）

菜单 **设置 → 偏好设置…**（`Ctrl+,`）。左侧五个分区，对齐 Typora 的偏好设置，但**只保留对简牍成立的选项**——
Typora 的更新 / 许可证 / Typora 服务器 / 图片上传服务 / Pandoc 多格式导出在这里都不存在（我们没有那些东西）。

| 分区 | 选项 | 落点 |
| --- | --- | --- |
| 外观 | 主题、主题文件夹、正文字体 / 字号 | `config.themeName` / `fontFamily` / `fontSize` |
| 外观 | **界面缩放 80–150%**（`Ctrl+滚轮` 也能调） | `webContents.setZoomFactor`，所有窗口一致 |
| 外观 | 显示底部状态栏 | `body.jd-hide-statusbar` |
| 编辑器 | **默认缩进 2 / 4 空格** | `indentList()` 的每级宽度 |
| 编辑器 | 代码块**行号** / **自动换行** | `#write` 上的 class，纯显示层 |
| 编辑器 | 新建代码块的**默认语言**（如 `cpp`） | `insertCodeBlock(view, lang)` |
| 编辑器 | **首行缩进** 2 字符 | 只作用于 `.jd-p`，不碰列表 / 引用 / 代码 |
| 文件 | 自动保存开关 | 关掉后只有 `Ctrl+S` 落盘（草稿仍每 300ms 写）；**已排上的那一轮会被撤销**，打开时若有未保存改动会立刻补存一次 |
| 文件 | 启动时打开上次的文件 | 关掉后停在空白页；**草稿那篇不受影响** |
| 图像 | 图片保存目录模板（`${filename}`）/ `./` 前缀 | `saveImage()` 的目录与引用写法 |
| 导出 | 导出 PDF 后在资源管理器里定位 | `shell.showItemInFolder` |

**唯一真相源**：`src/shared/prefs.ts`。默认值、夹值规则（缩放 0.8–1.5、缩进只认 2/4、语言标记的合法形状）
都在那里，主进程与面板都只信这一份；它是零依赖的，所以 `pnpm test` 能直接断言。

### 三个实现上的硬约束

1. **不能写内联样式**。行号 / 换行 / 首行缩进都靠 `#write` 上的 class —— 主题也想给
   `.jd-code-line` 写规则时，class 能和它共存，内联样式则会不可逆地压过去。
2. **改完必须 `requestMeasure()`**。行号多一条左内边距、自动换行让行变高、状态栏消失让可视区
   多 26px —— 这些都是 CM6 的高度表**看不见**的变化，不重测就会点错行（同主题异步注入那个坑）。
3. **保存必须串行**。连点四个开关会并发四次 `setPrefs`，主进程每次「读配置 → 合并 → 写盘」，
   交错读到同一份旧值、响应还可能乱序回来 → 内存里的 prefs 被过期响应覆盖。
   实测表现：磁盘上四项都存对了，界面上只剩 `jd-code-lineno`，换行与缩进当场失效。
   渲染层与主进程各排一道队（`renderer/prefs-state.ts` / `config.ts`）。
   **读也走同一条队**：面板打开时正好有保存没落完，读到的旧值会反过来覆盖内存态
   （刚点开的开关自己弹回去）。需要「值变了才做」的副作用（缩放）走 `setPrefs` 的
   `onApply`，在队列内部拿（新值, 旧值）—— 在队列外面自己取旧值比较，并发时判断是错的。

## 快捷键设置

菜单 **设置 → 快捷键…**。**51** 个命令都可改（打开笔记库 / 保存 / 查找 / 标题 1–6 / 正文 / 加粗 / 斜体 / 行内代码 / 代码块 / 提升·降低标题级别 / 引用 / 三种列表 / 表格 / 警告框 / 大纲与源码模式 / 偏好设置 / 快捷键面板本身…），按 文件 3 / 编辑 1 / 格式 17 / 段落 24 / 视图 4 / 设置 2 分组。

- **点按键框 → 按下组合键 → 立刻生效**，没有「应用」按钮
- 底栏实时给原因：只按了修饰键 / 没带 Ctrl·Alt·Shift / **这个组合已被某命令占用**
- 每行右侧 `↺` 恢复该项默认，底栏可一键全部恢复
- 只存改过的项（`config.keymap`），默认值永远以 `shared/commands.ts` 为准 ——
  以后调默认键不会和用户配置打架

**唯一真相源**：`src/shared/commands.ts` 的 `COMMANDS`。主进程用它生成菜单的 label 和
accelerator，设置面板用它渲染列表。加一个新快捷键只需在表里加一行 + 菜单里 `mi('cmd')`。

### 这里有个必须绕开的坑

Electron 的菜单快捷键是在**主进程**处理的，渲染层收不到那个 keydown。所以想把已经绑给
「保存」的 `Ctrl+S` 改走时，一按就触发保存，录制框什么都不显示 —— 看起来像「按了没反应」。

解法：进入录制时调 `keymap:capture` 让主进程把菜单上的 accelerator **全部摘掉**（`captureMode`），
录完再挂回去。另外监听要挂在 `window` 的 **capture 阶段**并 `stopPropagation`，
否则 CM6 会先吃掉按键，表现一模一样。

实测（自动化 CDP）：录制中按 `Ctrl+S` → 渲染层成功接住并提示「已被『保存』占用」，保存未被触发。

### 又一个坑：CM6 会抢菜单快捷键

菜单 accelerator 和 CodeMirror 自己的 keymap 会争同一组按键，**CM6 常常赢**。

实测把「代码块」按 Typora 习惯绑到 `Ctrl+Shift+K`：按下之后文档**少了一行**——
CM6 执行了它的 `deleteLine`，我们的命令根本没跑，还不报错。更隐蔽的是 `Ctrl+I`
正好是 CM6 的 `selectParentSyntax`，而那是「斜体」的默认键。

所以 `renderer/keybindings.ts` 在 window 的 **capture 阶段**统一接管：
命中命令就执行并 `stopPropagation`，CM6 的 handler 挂在内容元素上（target 阶段），
永远晚一步。菜单那边仍保留 accelerator（当说明书用），两条路径都调同一个
`runCommand`，60ms 去重防止两边同时到达时把「加粗」裹成两层。

## 启动流程与耗时（4.6.0 优化）

启动是一条 await 链，**慢在哪必须量出来**，不能猜。`main.ts` 里有一组 `bootMark()` 打点，
把每个阶段结束时的 `performance.now()` 记进 `window.__jdBootTimings`（打包版也能读，不需要
DevTools profiler）。245 篇的真实库、同一台机器上量的中位数：

| 阶段 | 优化前 | 优化后 | 说明 |
| --- | --- | --- | --- |
| 模块求值（bundle 解析 + 执行） | 181ms | 185ms | 入口 chunk 1.2MB，绝大部分是 CM6 本体。**这是地板**，见下 |
| 并发读配置（库/主题/上次文件/草稿/自动保存/侧栏宽） | +31ms | **+2ms** | 原来 6 个 IPC 串着等，改成一次 `Promise.all` |
| 列主题 + 应用主题 + 字体字号 | +21ms | +58ms | 变慢是因为文件树挪到这里**并行**做了（总时间仍是净减） |
| 文件树就绪 | +95ms | **+0ms** | 只读一层 + 默认收起 + 懒建 DOM，且在开笔记的同时并行 |
| 打开笔记（`openNote`） | +164ms | **+58ms** | 裂图检测改非阻塞、大纲/字数延后到下一轮 |
| **启动完成**（所有 await 结束） | **494ms** | **310ms** | **−184ms / −37%** |
| 首帧（用户真正看见） | — | 343ms | 4.6.0 起才打这个点 |

三个具体做法：

- **能并发的 IPC 一次全发出去**：`getLibrary`/`getCurrentTheme`/`getLastFile`/`getDraft`/
  `getConfigError`/`getAutosaveMs` 互不依赖，串行时大部分时间在"排队"而不是干活。
- **文件树不再全量扫**：`listTree` 递归整棵树（245 篇 60ms+），而收起状态下这些节点连 DOM
  都不建 —— 改用 `listDir` 只读顶层，展开时再要那一层（`fs:listDir`）。同时子节点**不预先建 DOM**：
  启动时只画十几行，不再是 822 个节点。
- **打开笔记只做"上屏必需"的事**：裂图检测（36ms 的一次目录扫描）不再挡在大纲前面，
  改成算完补一句状态；大纲/字数/表格浮条放到下一轮事件循环 —— 正文先出来。

**为什么不去拆 bundle**：入口 1.2MB 里 CM6（`@codemirror/view` 一个就 483KB 未压缩）是首屏必需，
`mermaid`/`elk`（3MB）本来就是动态 chunk。`postcss`（主题翻译）也在首屏链路上。
真要再压，下一个候选是**把翻译结果按主题文件 mtime 缓存到磁盘**（`applyTheme` 目前每次启动
都重新跑一遍 postcss，约 30ms）—— 但那要连缓存失效一起设计，没在这一版做。

## 文件树：默认全收起 + 懒加载（4.6.0）

打开软件时文件树**只有顶层**，每个目录都是收起状态（三角朝右），点一下才展开、才去读盘。

- `expanded` 是一个模块级 `Set<path>`，**不做持久化** —— 用户要的就是"每次打开都收起"。
- 子节点**不预先建 DOM**，不是 `display:none`：所以 `renderTree` 从 35ms 降到 1ms 级，
  滚动容器也不会被几百个隐藏行撑出假高度。
- 目录第一次展开才发 `fs:listDir`，结果写回 `node.children`（`undefined` = 还没读过，
  `[]` = 读过是空的 —— 空目录展开后折角直接藏掉，不然用户会对着展不开的三角反复点）。
- 刷新（外部改动 / 换库）时**已展开的目录保持展开**：数据来自 `listDir` 不带 children，
  所以会再要一次，而不是塌成空白。
- 当前笔记的高亮用 `samePath()` 比较（正斜杠 vs 反斜杠）：配置里的 `lastFile` 是正斜杠、
  树的 `title` 来自 `path.join` 是反斜杠，直接 `===` 会让"启动时打开的那篇"不高亮（这条修于 4.6.0）。

## 文件面板的右键菜单（4.8.0）

在侧栏「文件」面板里**右键任意一行**（或空白处）弹出菜单，11 项，与 Typora 的文件面板同名同序：

| 菜单项 | 作用 | 触发/作用于 |
| --- | --- | --- |
| 在新窗口中打开 | 开一个副窗口，只看/编辑这一篇 | 右键**文件** → 打开该文件；右键目录或空白 → 打开上次那篇 |
| 新建文件 | 建一篇空 `.md` 并**立即打开** | 目标目录 = 右键的目录本身 / 文件所在目录 / 库根 |
| 新建文件夹 | 建一个目录 | 同上 |
| 搜索 | 聚焦侧栏搜索框，把当前名字填进去 | 任意位置（名字取右键节点的名字，去扩展名） |
| 文档列表 | 切到**平铺**视图（一行一篇，右侧灰字显示所在目录） | 任意位置，菜单里带勾 |
| 文档树 | 切回树视图 | 同上，两者互斥 |
| 重命名 | 改文件名/目录名 | 仅节点；**库根不可用**（灰掉） |
| 删除 | 移到系统回收站 | 仅节点；**库根不可用**（灰掉），红色警示 |
| 属性 | 名称/类型/大小/修改时间/位置/字数 | 任意位置（空白 = 库根） |
| 复制文件路径 | 复制绝对路径到剪贴板 | 任意位置 |
| 打开文件位置 | 在资源管理器里定位 | 任意位置 |

行为上的几个约定：

- **新建的文件名不写扩展名会自动补 `.md`**；重命名时**不写扩展名沿用原来的**
  （把 `笔记.md` 改成 `笔记` 不该丢掉 `.md`，丢了文件就从树里消失了）。
- **名字校验**：空、`.`/`..`、点开头、`\ / : * ? " < > |`、超过 120 字一律拒，
  输入框里当场红字（主进程 `checkEntryName` 是最终裁决，前端只是即时反馈）。
- **删除是两级**：先确认 → 走系统回收站；回收站被系统拒绝（企业策略/网络盘/受限沙箱会
  直接抛 `Failed to perform delete operation`）→ **再弹一次**明确的「永久删除」，绝不静默降级。
- **重命名正在编辑的那篇**：只改 `current.path`，**不重新读盘**（重读会冲掉没保存的改动）；
  重命名它的**父目录**时按前缀替换，并把树的展开状态一起搬过去（`renameExpanded`）。
- **删掉正在编辑的那篇**：必须把 `current` 摘成 `null`，否则 800ms 后自动保存会把文件
  **重新写回磁盘**——用户看到的"删除"等于没删。

### 多窗口是怎么加的（`win:new`）

`createWindow(opts)` 现在支持 `{ file, secondary }`：副窗口在 URL 上带 `?file=...`，
渲染层启动时优先打开它；**不改 `mainWindow` 指向、不保存窗口位置、不写 `lastFile`**
（否则在副窗口里翻两篇，主窗口下次启动就打开了它最后看的那篇）。
关窗保护也从「一个布尔量」改成 `dirtyWindows: Set<webContents.id>`——按窗口各记各的，
不然副窗口改几个字会让主窗口关窗时也弹「还有未保存的修改」。

### 这里的坑

| 坑 | 现象 | 修法 |
| --- | --- | --- |
| 删除后文件又自己回来了 | 删掉正在编辑的那篇，0.8 秒后它又出现在磁盘上 | `doSave()` 对 `current == null` 直接返回 true，所以删除后必须把 `current` 摘掉（`onFileTrashed`） |
| 回收站不可用时静默永久删 | 有的环境 `shell.trashItem` 直接抛错，点「删除」永远删不掉且没有解释 | 主进程返回 `forceAvailable`，渲染层弹**第二次**确认，用户点头才走 `fs:remove` |
| 点菜单外面关菜单，却打开了别的笔记 | 用 `click` 关菜单，mousedown 已经落到下面的树行上 | 关闭监听用 `mousedown`（capture），菜单项自己用 `click` |
| 目录改名后当前笔记在树里"消失" | `expanded` 里存的是旧路径，重画后目录变回收起，`is-active` 无处可挂 | `renameExpanded(old, new)` 把展开状态跟着搬 |

### 文件夹与文件怎么区分（4.9.1）

截图反馈的问题：两者原来都是**同一种浅灰实心图标、同 13px、同字重** —— 深色背景 + 小尺寸下，
形状那点差异基本看不出来。单靠一个维度不够稳，现在**四个维度同时区分**：

| 维度 | 文件夹 | 文件 |
| --- | --- | --- |
| 形状 | **实心**（左上带标签的标准文件夹轮廓） | **细线描边**（空心，像一页纸） |
| 颜色 | accent 青 `#00c4b6` | 中性灰 `#9fa8b2` |
| 尺寸 | 14px | 12px |
| 文字 | 600 字重 + `#e4e9ee` | 400 字重 + `#b8bfc7` |

另外给子级加了**缩进引导线**（父行图标位置垂下一条 `rgba(255,255,255,.07)` 的竖线）——
多层嵌套不再只靠左边距猜。引导线位置由 `tree.ts` 按 depth 写进 `--jd-guide`（`24 + depth*16`），
CSS 用 `.jd-children::before` 画。

三种状态（默认 / 悬停 / 选中）都有明确规则：

- **默认**：上面那张表；
- **悬停**：整行 `#262626` + 文字与图标都变纯白（文件夹图标变"青偏白"，保持色相）；
- **选中**（当前打开的那篇）：行底 `rgba(255,255,255,.13)` + 纯白字 + 纯白图标。

⚠ 两个容易踩的点：

1. **颜色语义要守住：青 = 容器，灰/白 = 内容**。所以"当前打开的那篇"高亮时图标变**白**而不是变青 ——
   变青会和文件夹撞色，用户反而更分不清。
2. **引导线必须 `pointer-events: none`**：它是一条绝对定位的 1px 竖线，压在子行的左侧；
   不设 none 会挡住行的 `mousedown` / `dragover`，表现是"偶尔点不动、拖不进去"这种极难复现的毛病。

## 拖拽移动（4.9.0）

在文件面板里**按住一行拖到另一个目录上松手**，文件/目录就移动过去了。

| 动作 | 结果 |
| --- | --- |
| 文件 → 目录行 | 移到那个目录里 |
| 文件 → 另一个文件行 | 移到**那个文件所在的目录**（和资源管理器一致） |
| 文件/目录 → 树的空白处 | 移到**笔记库根目录** |
| 目录 → 收起的目录上停 0.7 秒 | 自动展开它（不用先松手、点开、再拖一次） |
| 拖到库外/别的地方 | 什么都不发生 |

拖动时：拖起来的那行变淡，能放的那行亮青色虚线框；松手后树立刻刷新，状态栏提示「已移动到「xxx」」。

**拒绝的情况**（不亮框、松手也没反应，不是"拖了没效果"的 bug）：

- 拖到自己身上；
- 把目录拖进**它自己或它的子孙**（会得到一个打不开的环）；
- 目标目录里**已有同名文件** —— 状态栏提示「目标文件夹里已经有「x.md」了」，**不覆盖**；
- 已经在那个目录里（提示「已经在这个文件夹里了」）；
- 跨磁盘（`EXDEV`）：明确提示不支持，不做"复制 + 删源"。

### 三个实现要点

1. **只 `setData('text/plain')`，绝不放 `Files`**：一旦 dataTransfer 里带 `Files`，Electron 会把这次拖拽
   当成"拖出一个真实文件"，拖到资源管理器的窗口上就绕过我们的校验直接移动/复制 —— 那是真的动磁盘。
2. **放置侧绑在容器上**（行会随展开/收起重建），靠 `closest('.jd-node')` 反查；`dragover` 必须
   `preventDefault()` 才允许 drop —— 所以"不能放"就是不调它，光标自然变成禁止符号。
3. **移动后必须同步三件事**：`renameExpanded(src, dest)` 搬展开状态、`current.path` 换前缀
   （否则下一次 Ctrl+S 会写到**旧路径**、把文件重新创建出来）、`flatCache = null`
   （列表/搜索视图才看得到新位置）。**不重读盘** —— 移动不改内容，重读会冲掉未保存的改动。

高亮用 `outline` 而不是 `border`：加边框会把行撑高 2px，整棵树跟着抖一下。`user-select: none`
也是必须的，否则按住行往下拖会先把文件名选中（一片蓝）。

## 文件树：视觉对齐 Typora（4.7.2）

侧栏「文件」面板照 Typora 的同款面板量了一遍像素，只改样式、不动功能：

| 项 | Typora（截图量得） | 我们改前 | 改后（实测） |
| --- | --- | --- | --- |
| 行高 | 29px | 25px（上下各 3px padding） | **30px**（上下各 5px） |
| 字号 | 13px | 13px | 13px（一致） |
| 每级缩进 | 16px | 20px | **16px**（12 / 28 / 44…） |
| 三角 / 图标 / 文字 x | 17 / 25 / 42 | 5 / 19 / 36 | **11 / 25 / 42** |

| hover 背景 | #262626 | #242424 | **#262626** |
| 打开的那篇 | 淡白底 | 蓝底 #2d5c8a（很抢） | **rgba(255,255,255,.12) + 纯白字** |

- 缩进写在 `tree.ts` 的行内 `paddingLeft`（`12 + depth*16`）：行是 `flex`（三角 + 图标 + 文字），

- 行高/颜色/hover/选中都在 `style.css` 的 `.jd-node` 一族里，**没有动结构、没有加菜单**。

**没跟的两处（都属于功能，不是样式）**：
① Typora 会把笔记库根目录本身画成第一行（带"打开的文件夹"图标），我们直接列内容；
② Typora 的文件名带 `.md` 后缀，我们的树里把它省掉了。要改都只是一两行的事，说一声就改。

## 行内标记：藏掉星号，但语义要留下（4.7.1）

用户截图里的问题是：**大纲把 `### **1. 结论**` 的星号原样显示出来了**。顺着查下去发现更严重的一条 ——
编辑器里 `**加粗**` 只把星号藏了，**文字并没有变粗**（`*斜体*` 同理），也就是"语法没了，意思也丢了"。

现在两处都修了，原则是**渲染层只做视觉，文档一个字节不改**：

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| 大纲（侧栏） | `**1. UMG 和 Slate 是什么关系？**`（露星号） | `1. UMG 和 Slate 是什么关系？` |
| 正文 `**粗**` | 星号藏掉，文字仍是 400 | 星号藏掉 + 内容挂 `.jd-strong`（**700**） |
| 正文 `*斜*` | 星号藏掉，文字不倾斜 | 挂 `.jd-em`（italic） |
| 正文 `~~删~~` | 星号藏掉，没有删除线 | 挂 `.jd-del`（line-through） |
| 正文 `***又粗又斜***` | 同上 | 一个 mark 挂两个 class |
| 正文 `1~2~3` | 单个 `~` 被当成标记藏掉 | **不当标记**（单波浪号不是语法） |

实现分三块：

1. **`renderer/inline-text.ts`（纯函数，可单测）**：`plainInlineMarkdown()` 把一段行内 markdown 变成
   "看起来的样子"。只做减法：去 `**` `*` `_` `~~` `==`、链接/图片只留文字、HTML 标签只留内容、
   `\*` 还原成 `*`。**行内代码整段先摘出来**（`` `a**b**c` `` 里的星号是字面量），**成对且内侧非空格才算标记**
   （否则 `a * b * c` 这种算式会被吃掉）。`headingText()` 改成走它 → 大纲天然干净。
2. **`markers.ts`**：强调分支现在除了藏开闭标记，还会给内容发一个 mark 装饰（`.jd-strong`/`.jd-em`/`.jd-del`），
   并**递归扫一遍内容**处理嵌套（`**粗 *斜* 粗**`）。
3. **`mapping.json`** 补了 `strong/b → jd-strong`、`em/i → jd-em`、`del/s → jd-del`：主题里的
   `#write strong{…}` 翻译后正好落到 `#write .jd-strong`，**字重与颜色仍由主题决定**
   （rider-dark 是 700 + `#d7dae0`），theme-base 只放裸类名兜底（0,1,0，主题永远赢）。

顺带修了标题阶梯：`h5`/`h6` 原来都是 `1em`，和正文一样大、只剩加粗可言 —— 六级标题实际退化成两级。
现在 `h5 0.9em` / `h6 0.85em`（Typora 默认是 0.875 / 0.85）。⚠ 这条改在**主题**里
（`src/theme/rider-dark.css`），已装副本 `<userData>/themes/rider-dark.css` 与 `纯净版/userdata/themes/` 也同步了，
否则老用户看到的是旧值。

**光标行仍然显示源码**（`**粗**`、`##` 都在）—— 这是刻意的，与 Typora 一致：要编辑标记的时候得看得见它。

## 大纲：对齐 Typora（4.7.0）

侧栏「大纲」照着 Typora 的同一块面板量了一遍，改动如下（数值都是从截图里量的像素）：

| 项 | Typora | 我们改前 | 改后 |
| --- | --- | --- | --- |
| 一级标题文字左边界 | 32px | 10px（还会按最小级别整体归一） | **32px** |
| 每级缩进步长 | 14px | 12px | **14px**（46 / 60 / 74…） |
| 字号 / 行高 | 14px / 27px | 12.5px / 18.75px | **14px / 26.6px（行距 27）** |
| 层级字重 | 各级一致，不加粗 | lv1 600 / lv2 500 | **不加粗** |
| 查找 | 顶部输入框 + 右侧 ✕，下面一条分隔线 | 无 | **有**（输入即过滤，Esc / ✕ 清空） |
| 当前章节 | 整行浅色底 | 青色左竖条 + 淡青底 | **整行浅色底 + 文字提亮** |
| 折叠三角 | 没有（纯缩进） | 没有 | 没有（一致） |

- 缩进**不做「最小级别归一」**了：全篇从 `##` 开始的笔记，整体缩进一格 —— 和 Typora 一样以
  「标题的真实级别」为准，而不是「这篇里最小的级别」。
- 过滤只筛标题文字（大小写不敏感的子串），**缩进层级原样保留**，这样还能看出命中项属于第几级。
- 空状态分两种文案：「这篇没有标题」/「没有匹配的标题」。

### ⚠ 这里的坑：侧栏里的排版全被 `shell-guard.css` 按住了

`shell-guard.css` 有一条 `#jd-sidebar, #jd-sidebar * { line-height: 1.5; font-family: … }`，
用来挡 Typora 主题里的 `div{}` / `*{}`（不挡的话侧栏会被刷成白板）。它是 **(1,0,0)、而且在
`style.css` 之后加载**：

- 只写 `#jd-outline { line-height: 1.9 }` 也是 (1,0,0) → **输在先后顺序上**，行高被悄悄压回 1.5。
  之前那句 `line-height: 1.45` 就是这么一直没生效的（实测 18.75px = 12.5 × 1.5，肉眼很难发现）。
- 更要命的是 `#jd-sidebar *` **直接命中每一个大纲行**，而"直接声明"永远赢过"继承" ——
  所以行上还得显式 `line-height: inherit`，否则外层设成 1.9 也白搭。

结论：**侧栏里新增任何排版规则，选择器都要带 `#jd-sidebar` 前缀**（(1,1,0) 起），
并且给需要继承行高的子元素补 `line-height: inherit`。

## 折叠 / 专注 / 打字机

三个阅读向功能，都只改「怎么看」，**不动文档一个字节**。

### 折叠（`renderer/fold.ts`）

- 标题折叠到下一个「同级或更高级」标题之前，代码块折叠到闭合围栏。用栈一趟扫完，O(n)。
- 收起的内容用 `Decoration.replace({ block: true })` 从**布局**里换掉。**不能**用 CSS `display: none` ——
  CM6 的高度模型不知道被 CSS 隐藏的行，隐藏之后滚动、点击、光标会全部偏移（和「行级 margin」是同一个坑）。
- **含表格行的块不可折叠**：一张表本身就是一个 block replace，两个 replace 覆盖同一段，CM6 会直接抛错。
- 折叠区间对光标是**原子**的（`EditorView.atomicRanges`）。否则光标会停在没有 DOM 的行里 ——
  看不见光标，但打字确实会写进去，这是最难排查的一类问题。
- 折叠状态存**行首位置**而不是行号，靠 `tr.changes.mapPos()` 跟着编辑走。`setDoc` 走的是
  `EditorState.create`，所以换笔记时折叠状态天然清空，不需要手动展开。

### 专注模式

`.jd-active` 由 `lineclasses.ts` 按**段落**给：空行 / 标题 / 列表项 / 分隔线 / 表格 / 围栏标记算边界，
代码块内部不设边界（整块算一段）。只给光标那一行加是错的 —— 写着写着整段一起亮才叫专注。

淡化用 `opacity` 而不是改 `color`：后者会覆盖主题的正文色，前者是"整段退场"，符合意图。

### 打字机模式

把光标行滚到视口正中，**必须自己算 `#write.scrollTop`** —— 滚动容器是 `#write` 而不是 `.cm-scroller`，
`EditorView.scrollIntoView()` 在这里无效（同一个坑见下表）。

### 两个 toggle 都踩过同一个坑

「专注模式」「打字机模式」都是 toggle。菜单 accelerator 还在主进程注册时，按键会被**两条路径各触发一次**：
开完立刻关，按下去像完全没反应，状态栏还显示回到「视图：常规」。60ms 去重挡不住（IPC 到达间隔偶尔超过 60ms）。

解法是菜单项加 `registerAccelerator: false` —— accelerator 只用于**显示**（当说明书），按键一律交给
渲染层 `keybindings.ts`。现在只剩一条触发路径，行为可预测。

## 表格面板 / Mermaid / 源码模式 / PDF

### 表格面板（`table-panel.ts`）

光标进表格时浮出工具条：±行、±列、左中右 / 默认对齐。

- **浮在窗口底部**而不是贴着表格：贴表格要跟着滚动、折叠、换主题重算坐标，还得处理贴边翻转；
  而光标在表内时表格本来就退回源码行，视线就在那一块，底部固定条够得着也不会跑偏。
- 按钮监听 `mousedown` 并 `preventDefault`：焦点一旦离开编辑器，selection 就变了，
  面板会立刻自己藏起来 —— 用户看到的是"点了一下面板就没了"。
- 表头行和分隔行删不得（删了表格就不成立），按钮置灰。
- 列索引靠 `columnAt()` 数竖线，不在 `splitRow` 结果上做偏移映射（转义 `\|`、首尾缺竖线都会把偏移算错）。

#### 列对齐（4.4.0）

菜单「段落 → 表格 → 对齐」、底部工具条、快捷键面板三条入口**同一份实现**（`editor.ts` 的
`alignTableColumn` + `table-parse.ts` 的 `setColumnAlign`）。GFM 里列对齐只有一种表达 ——
分隔行那一格的首尾冒号：`---` 默认 / `:---` 左 / `:---:` 居中 / `---:` 右。作用范围是
**光标所在那一列**，与 Typora 一致。

三条约束（都是"纯文本是唯一真源"的直接推论）：

- **只动那一格的冒号**，短横线数量与整行空格风格原样保留。`|---|:--:|---|` 改第 1 列右对齐得
  `|---:|:--:|---|`，不会变成 `| ---: | :-: | ---: |` —— 早期版本用 `joinRow` 重建整行，
  等于顺手把用户的文件格式化了。
- **只改分隔行**，不碰表头与数据行；一次 dispatch，一步撤销。
- 不是分隔行、或列号越界 → 返回 `null` 直接拒绝，不硬写（`setColumnAlign` 先跑 `parseAlign` 校验）。

### 为什么没有多光标（4.4.0 移除）

Typora 不支持多光标，本项目的定位是**严格对齐它的交互**，所以
`EditorState.allowMultipleSelections` 是关的（`editor.ts` 里留了注释说明怎么开回来）。

原因不只是"保持一致"：CM6 判定加光标的条件是 `allowMultipleSelections && (mac ? metaKey : ctrlKey)`，
而在 Windows 上 **Ctrl+点击** 正好是"在新标签页打开链接"的肌肉记忆 —— 笔记里随手一个 URL 就会误触，
之后两根光标同时打字，很容易把一行删掉一半。要恢复多光标，放开那一行即可。

### 代码块语言（`code-lang.ts` + `lang-picker.ts`，4.5.0）

光标不在代码块里时，块右下角有个小徽章写着当前语言（`cpp`），点开是可搜索的语言列表，
选中即改写**开启围栏**那一行；没写语言的块显示虚线的「语言」。

- **只改语言那一段**：` ```cpp title="x" ` → ` ```python title="x" `，其余字节不动（`code-lang.ts` 的 `fenceLang`/`withLang`，有单测）。
- **写进文件的是短名**（`C++` → `cpp`）：CodeMirror 的大小写无关匹配覆盖 name 与 alias，但 Typora/GitHub 的惯例是短名。
  列表里显示的仍是全名。
- 语言表直接用 `@codemirror/language-data` 的 `languages` —— 与 `markdown({codeLanguages})` 同一份，不另抄；
  只读 name/alias，**不触发语言包的动态 import**。
- ⚠ **徽章挂在最后一行代码上，不是闭合围栏行**：围栏行被压到 35% 亮度，徽章颜色由 `currentColor` 派生，
  挂那儿会跟着变灰、几乎看不见（这是实测踩到的）。
- ⚠ **必须绝对定位**：内联元素会把行撑高，CM6 的高度表与真实 DOM 脱节 → 点击/选区整体错位（同 theme-fix 开头那条）。
  定位基准是 `.jd-code-line` 的 `position: relative`（只建包含块，不改尺寸）。
- 点击要 `preventDefault`：否则光标跳到该行、该行变活动行，徽章当场消失、浮层失去锚点。
- 长代码块滚到中间时，闭合围栏还没进视口 → 徽章不出现（滚到底即可），这是"只处理可见范围"的必然。

### Mermaid（`mermaid.ts`）

- **按需动态 import**：库压缩后三兆多，首屏不该背它；文档里真出现 ```mermaid 才加载。
- **结果按 `(明暗档, 代码内容)` 缓存**：滚动、换光标都会反复要求同一张图，不缓存等于每次重跑一遍布局。
  键里必须带明暗档 —— `mermaid.render` 把颜色烤进了 `fill`/`stroke` 属性，跨主题复用就是深色底浅色字。
- **`initialize` 的全局状态集中管**：`applyMermaidTheme()` 记住当前档位、只在档位变了才调。
  导出时用 `withLightTheme()` 临时切浅色，`finally` 里还原（导出的是白底纸面，图也得浅色）。
- **异步结果靠 effect 回流**：block 装饰必须由 StateField 提供，而它的 update 是同步的、不能 await；
  渲染完成后 dispatch 一个空 effect，把"可以重算了"这件事推回 state。
- 光标进块退回源码；点图也能进块 —— `ignoreEvent()` 必须返回 `false`，否则点击被 widget 整个吞掉。

### 源码模式（`viewmode.ts`）

一个布尔 field，四个模块读它：markers 不出标记装饰、table 不画表格、fold 不折叠、mermaid 不替换。
行级 class（`.jd-h1` / `.jd-code-block`）保留 —— Typora 的源码模式也保留排版，只是把标记露出来。

换笔记时 `setDoc` 走 `EditorState.create`，field 会重置成 `false`，所以 `sourceMode` 单独存了一份变量补回去，
否则翻下一篇就悄悄退回渲染模式。

### PDF 导出

**没有走 pandoc**：本机根本没装（策划案里"本机已装 pandoc"那句话已经过期），
而让用户为了导出再装一个外部二进制不合适。

改成 `markdown-html.ts` 用**编辑器同一个 Lezer parser** 生成 HTML（markdown 解析仍然只有一份实现），
套上当前主题的翻译结果，交给隐藏窗口 `printToPDF` —— 纸面和屏幕是同一套 CSS。

**为什么不直接打印主窗口**：CM6 是虚拟化的，屏幕上只有视口那几十行有 DOM，直接打印会得到大片空白。
隐藏窗口里放的是静态 HTML，全文都在。

**mermaid 会被换成真图**（`mermaid-export.ts`）：静态 HTML 那条路上没有任何 widget，所以单独再走一遍——
从 Lezer 树上按顺序摘出所有 ```mermaid 源码，逐个渲染成 SVG，再按**出现顺序**把
`<pre class="jd-code-block"><code class="language-mermaid">…` 换掉。按顺序而不是按文本匹配，
是因为同一段源码出现两次时按文本替换会把两处都换成同一张图。渲染失败保留代码块（图和原文都在 PDF 里）。
颜色用 `withLightTheme()` 临时切浅色档 —— 导出页是白底，深色图很别扭；而 `initialize` 是全局的，不还原会让编辑器里的图也变浅。

| 围栏缩进不能简单放宽 | 列表项嵌套会让围栏带 4–8 空格缩进（库内 183 行/10 文件），但代码块**内部**也有深缩进的 ` ``` `。把 `{0,3}` 直接改成 `{0,8}` 会让后者把块提前关掉，实测净减 8206 行。正解是「按开启时的缩进配对」：块内只有缩进 ≤ 开启缩进的围栏才算关闭（见 `renderer/fence.ts`） |
| 围栏行不能用 opacity 淡化 | 围栏行是代码块上/下边框的载体，`opacity:0.35` 会连 `border` 和 `background` 一起打到 35%，深色主题下「代码块看不出是块」就是这么来的。只淡化文字颜色（`color-mix`） |
| `.cm-scroller` 不是这个项目的滚动容器 | `style.css` 把 `.cm-scroller` 设成 `overflow: visible`（为了让主题的 `#write` 内边距/背景生效），真正滚动的是外层 `#write`。两个后果：`EditorView.scrollIntoView()` **不生效**；换笔记也不会自己回顶部。都得手动操作 `#write.scrollTop` |
| `requestAnimationFrame` 在窗口不可见时**完全暂停** | 最小化 / 被遮挡 / 自动化里没抢到前台时 `visibilityState=hidden`，实测 600ms 内 rAF 回调 **0 次**。任何「滚动定位 / 延迟校正 / 动画」都不能只挂 rAF——表现是「点了没反应」，而且只有特定环境才复现。改用 `setTimeout` 链（隐藏页面只是节流，不会彻底停摆） |
| 滚动定位要迭代校正 | CM6 对没渲染过的行只有**估算**高度，滚过去之后才真正渲染、内容重排，位置又偏了（实测一次校正在靠后标题上偏 400px）。做法是递增延迟 30/60/90ms 连校 3 轮，误差收进 4px |
| 限宽别加在滚动容器上 | 想让正文占 90% 时，`max-width` 一度写在 `#write` 上——而 `#write` 就是滚动容器，滚动条跟着被拽到 90% 处，右边留一大条空白，看着像滚动条脱离了窗口。限宽必须下沉到不参与滚动的 `.cm-editor`，滚动条才贴得住窗口右缘 |
| `::-webkit-scrollbar-thumb` 的 `currentColor` 是**容器**的颜色 | 所以滚动块颜色可以直接从主题正文色派生，不用为每个主题配一个滚动条色。但主题若写了 `background: var(--scrollbar-color) !important`（dyzj 系列就是这样），主题赢——这是主题的表达，别去压 |
| 光标是纯黑的，和主题没关系 | CM6 默认 `.cm-cursor { border-left: 1.2px solid black }`，深色适配那条是 `&dark .cm-cursor`——只有用过 `EditorView.theme(…, {dark:true})` 才会生成 `.cm-dark` 类。本项目颜色全交给 Typora 主题，`.cm-dark` 永远不存在，所以深色主题下光标一直是黑的（实测 `hasCmDark: false`）。改为 `border-left-color: currentColor` 跟随正文色，且**必须带 `#write` 前缀**（1,1,0）：CM6 的样式是运行时注入到 `<head>` 末尾，同特异性它赢 |
| ↑/↓ 一按就「冲到选区另一头」 | CM6 的 `cursorByLine` 对**非空选区**直接执行 `rangeEnd(range, forward)`：`↑` 把光标放到选区 from、`↓` 放到 to，**塌陷之后不再移动**。选中一个 20 行的代码块、在底部按一下 `↑`，光标瞬间移到块首，看着就像「直接到顶部」。现在 `editor.ts` 用 `arrowFromCursor()` 提前接管：从 `head`（用户最后一次拖到的位置）起步移动一行。只在「单光标 + 有选区」时接管，其余交回默认实现 |
| 列表项里的标题也是标题 | 库里 **50 个文件、232 行**写成 `- ## 标题`（多半是从网页复制时被套上列表符号）。原来的标题正则只认行首 `#`，于是这些行既不是标题、也进不了大纲，`##` 还照样显示。现在 `heading.ts` 的 `parseHeading()` 同时认两种写法，行 class / 标记隐藏 / 大纲三处共用，`- ` 和 `##` 一起隐藏。普通标题仍然不允许前导缩进（放宽会把缩进代码块里的 `#` 误判成标题） |
| `KEY_ALIAS` 里的 `' ': 'Space'` 曾永远不生效 | `normalizeKey` 先走 `key.length === 1` 分支，而空格的 length 恰好是 1，别名永远轮不到 → 录出来的 accelerator 是 `CmdOrCtrl+ `（尾部一个空格），Electron 不认，绑定默默失效且无从排查。别名查询必须放在长度判断**之前**（`pnpm test` 的「键名别名」这条就是为它设的） |
| 折叠不能用 CSS 隐藏 | `display: none` 藏掉的行不在 CM6 的高度模型里，滚动/点击/光标会集体偏移。必须用 `Decoration.replace({ block: true })` 从布局里换掉。另外**含表格行的块不能折叠**——表格自己就是一个 block replace，两个 replace 重叠会抛错 |
| `gutterElement` 量到 `height: 0` 是假象 | 那是 CM6 的 `initialSpacer`（inline style 带 `visibility: hidden; pointer-events: none`），不是真实行标记。真实元素的高度由 CM6 按行量出来（标题 65px、正文 32px 各不同）。三角要用 `display: flex; align-items: center` 居中，靠 `line-height` 会让它偏到行的上三分之一 |
| toggle 类命令被两条路径各触发一次 | 菜单 accelerator 在主进程注册时，按键先被它吃掉、再走渲染层 → 「专注模式」开一次又关一次，按下去像完全没反应，状态栏还显示「视图：常规」。60ms 去重盖不住（IPC 到达间隔偶尔超过 60ms）。给菜单项加 `registerAccelerator: false`：只显示、不注册 |
| `pnpm dist` 在本机必失败 | electron-builder 打包前会 `emptyDir` 清空 `win-unpacked`，而本机的 safe-delete 是**按文件数**拦批量删除的（>50 个直接 block，报 `SAFE_DELETE_BULK_GUARD_ERROR`）。`pnpm pack` 把输出改到系统临时目录就绕开了 |
| 打包完的 `app.asar` 锁着删不掉 | 一个 549MB 的临时目录里其余文件都能删，只有 `app.asar` 被外部服务占着（实测等 90 秒、`Directory.Delete`、移动目录全失败）。所以临时目录**不要放在项目里**——`pnpm pack` 用系统 TEMP，不影响项目目录，系统迟早回收 |
| emoji 图标 ≠ 主题图标 | `📁`/`📄` 在 Windows 上是**彩色** emoji，`fill`/`color` 都管不了它，放在深色侧栏里比周围文字亮得多。侧栏/工具栏这类"跟着主题走"的图标一律用内联 SVG + `fill: currentColor` |
| 拖拽带 `Files` 会绕过校验 | `dataTransfer` 里一旦有 `Files`，Electron 把拖拽当成"拖出真实文件"——拖到资源管理器就等于直接移动/复制，我们的库内校验完全不起作用。拖拽只放 `text/plain` |
| 「删了又回来」= 忘了摘 current | 删除正在编辑的文件后，自动保存会把内容写回同一个路径 —— 文件复活、删除失效。凡是"让某个路径消失"的操作（删除、移库），都要确认自动保存不会往它写；`doSave()` 的 `current == null` 早退就是为此 |
| 藏标记 ≠ 保留语义 | `**粗**` 曾经只把星号 `font-size:0` 藏掉、内容不加任何样式，看起来"语法没了但也没变粗"。凡是"隐藏语法"的功能都要问一句：**原来的语义谁来承担？** 现在的做法是内容挂 `.jd-strong` 等 class，由主题给字重/颜色 |
| 侧栏样式被 `shell-guard` 静默压掉 | `#jd-sidebar *`（(1,0,0)，且在 style.css 之后加载）会把 line-height 钉在 1.5；只写 `#jd-outline` 同为 (1,0,0) 就会输。表现不是报错，是「数值对了但看不出变化」。排查靠 CDP 的 `CSS.getMatchedStylesForNode` 直接看命中规则，别靠猜 |
| 启动期一串 `await` 互相干等 | 6 个互不依赖的 IPC 串着等，实测 31ms 里绝大部分是排队。改成 `Promise.all` 后 2ms。同一类问题还有"把不挡首屏的活放在首屏链路上"：裂图检测 36ms、大纲/字数、整棵文件树 —— 它们都不该在正文出现之前跑 |
| 路径分隔符不统一 → `startsWith` 静默失效 | 配置里 `libraryRoot` 可能是 `D:/a`（正斜杠，被 Git Bash 的路径转换写进去的），而 `lastFile` 是 `D:\a`。`last.startsWith(root)` 直接返回 false，表现是「重启后停在文件树、不打开上次那篇」，**而且不报任何错**。比较前一律走 `normPath()` 统一分隔符和大小写 |
| 裸 CR 也算进了 CRLF 计数 | 老 Mac 风格的文件整篇只有 `\r`，原来它被记进 `crlf` 分支，于是 `eolStyle='crlf'`、`eolMap=null`，写回时每个 `\r` 变成 `\r\n` —— **字节数凭空翻倍**，git 里显示「全文重写」。裸 CR 现在单独成 `'cr'`（与别的混用时进 `'mixed'` 保留逐处序列）。这类损坏是最阴的一种：往返校验比的是「我们的编码器 vs 我们自己的解码器」，两边一起错就永远绿 |
| 非 UTF-8 文件读成乱码再写回 = 永久转码 | `Buffer.toString('utf8')` 遇到坏字节静默换成 `�`，不报错。所以「打开 → 自动保存」一条龙就能把 GBK 笔记变成一堆 `�`，且不可逆。判定必须用 `TextDecoder('utf-8', { fatal: true })`，保存路径上**先复检再动手**，非 UTF-8 一律拒绝写盘 |
| `fs.readFile(p, 'utf8')` 不剥 BOM | Node 不会替你去掉 `\uFEFF`（`JSON.parse` 会为此抛错，正则不会——所以更阴）。同一个库里有 4 篇带 BOM，`scanBrokenImagesOf` 曾直接走 utf8 读，首行紧贴图片语法时会漏判。凡是要按「文件原文」做正则的地方，统一走 `decodeBuffer()` |
| mermaid 的 SVG 把颜色**烤进属性**里 | `mermaid.render` 产出的是带 `fill`/`stroke` 内联属性的 SVG，主题里写 `.jd-mermaid path { fill: … }` 也压不过它（内联样式优先级最高）。所以换主题后复用缓存就是「深色底 + 浅色字」，而且**改 CSS 救不回来**，只能重渲染。缓存键因此带了明暗档（`d|l` 前缀），切主题时再 `cache.clear()` + 立刻重扫一遍 |
| `mermaid.initialize` 是**全局**的 | 它改的是库里的默认配置，下一次 `render` 才生效。曾经导出 PDF 时直接 `initialize({theme:'default'})` 图浅色好看了，代价是**编辑器里的图也一起变浅**，且永远回不去（下次打开还是浅色）。现在统一走 `applyMermaidTheme()` 记住当前档位，导出用 `withLightTheme()` 包起来，`finally` 里还原 |
| `URL(...)` 大写就失效 | CSS 里 `url()` / `URL()` / `Url()` 都合法，但 `decl.value.includes('url(')` 只认小写。症状是主题里某条背景图/字体声明被整段跳过，而报告里连一条警告都不给（连「丢弃」都算不上，压根没进改写流程）。判定一律用 `/url\(/i` |
| 同一套「隐藏目录」规则写了三份就会漂移 | `listTree`（文件树）、`scanBrokenImages`（全库扫图）、`verify-roundtrip` 的 `walk` 各有一份遍历逻辑。曾经只有 `listTree` 跳「点开头」，于是 `.主题/`、`.obsidian/` 里的 `.md` 也被算进裂图统计——文件树里没有的文件在统计里冒出来。现在统一 `shouldSkip()` + `MAX_DEPTH` + `collectMarkdownFiles()` |
| 指纹快路径会自己骗自己 | 为了省掉「每次保存都整篇读盘判编码」，用 `(mtime, size)` 指纹命中就跳过。但这俩值**正是渲染层从 `readNote` 拿到的**，一个从没被我们读过的 GBK 文件，它的 mtime/size 当然和刚 stat 到的一致——指纹百分之百命中，第二道防线形同虚设。现在快路径的前提是「主进程自己记账（`verifiedUtf8`）里，这个 path 的这个状态我亲自验过」；只传 `mtime` 不传 `size` 时退回保守行为 |
| 自己写盘触发的 watcher 会把文件树刷掉 | 自动保存 800ms 一次，每次写盘都触发 `fs.watch`，如果照单全收就要跟着 `listTree` 重画一遍——树的结构根本没变（只是某篇内容变了），但滚动位置和折叠状态全丢了。现在记 `selfSaveAt`，自写后 2 秒内只处理「当前篇变了没」 |
| `loadConfig` 静默回落像软件坏了 | 一个 `catch { cache = DEFAULT }` 把所有情况吞了：JSON 写坏、权限没了、手改漏逗号，表现都是「文件树空了 / 主题变回内置」，屏幕上**一个字都没有**。现在 `getLastLoadError()` 记下原因，主进程启动打日志、渲染层状态栏也提示。ENOENT 单独放过——首次启动不是错误 |

## 数据安全怎么做的

- **写盘**：tmp 文件 + `fsync` + rename（同目录，原子）；Windows 上被网盘/杀软占用时重试 6 次。
- **外部修改检测**：`SaveMeta.expectMtimeMs` 带上「打开/上次保存时看到的 mtime」，主进程在真正写盘**之前**比对磁盘现状，不一致就返回 `conflict` 而不写。渲染层弹确认框（覆盖 / 先不保存），用户点覆盖才带 `force: true` 重试。容差 1ms（网盘与杀软会重写时间戳）。
  - 为什么必须有：这篇在 Typora 里改过、网盘同步下来一版、或者 git 切了分支，自动保存会**双向静默吞掉**——本地这版盖掉对方的，对方那版也从编辑器里永远消失了。800ms 自动保存让这件事发生得毫无知觉。
- **不往非 UTF-8 文件里写 UTF-8**：`decodeBuffer` 用 `TextDecoder('utf-8', { fatal: true })` 判合法性，非法时 `validUtf8: false`。主进程 `writeNote` 先读盘复检，非 UTF-8 直接拒绝（`encoding: true`），磁盘一个字节不动；渲染层把编辑器锁成只读（`Compartment` 装 `EditorState.readOnly`，不重建 state，撤销历史与选区都留着），状态栏标「⚠ 非 UTF-8，只读」。
  - 为什么是拒绝而不是"尽力转换"：GBK/GB18030 文件读进来必然是 `�` 乱码，一旦按 UTF-8 写回，整个文件就被**永久转码**，原来能在 Typora 里正常打开的文件从此全乱，`Ctrl+Z` 也救不回来。宁可让用户看到乱码＋只读提示，也不做这种不可逆的事。
  - 复检不做成"每次保存都整篇读一遍"：280KB 的笔记每次保存多读一遍盘是纯浪费。用 `(mtime, size)` 指纹命中就跳过——但**指纹只认主进程自己记的账**（`verifiedUtf8` 这张 Map，只有 `readNote` 验过合法、或 `writeNote` 刚写成功时才记账）。渲染层传回来的 `expectMtimeMs`/`expectSize` 是它自己从 `readNote` 拿的，**不能**单独用来证明"这文件合法"：一个从没被我们读过的 GBK，它的 mtime/size 当然和刚 stat 到的一致。只信这两个字段，等于给刚打开的乱码文件开了一条写入通道。
- **外部改动自动同步**：主进程 `fs.watch` 笔记库（递归、只认笔记后缀、跳过点开头目录、500ms 防抖），发 `library-changed`；渲染层 120ms 再收一道，然后：文件树重画 → 当前篇 `readNote` 比 mtime → **没有未保存改动就自动重载**，有改动则只提示「你有未保存的改动，保存时会问你怎么处理」（绝不自动覆盖，和 `writeNote` 的冲突检测同一套标准）。
  注意这条提示之后**约 800ms 自动保存会真的撞上冲突并弹出原生确认框**——不是等你按 Ctrl+S 才问。这是刻意的：宁可当场问一句，也不能静默覆盖对方那版。
  - 我们自己写盘也会触发这个 watcher，所以记 `selfSaveAt`：自写后 2 秒内只处理"当前篇变了没"，不重画文件树。否则每 800ms 自动保存一次就把树重画一遍，滚动位置全丢，而树的结构根本没变。
- **崩溃恢复**：打字后 **300ms** 写一份草稿到**独立的 `draft.json`**（比 800ms 的自动保存更早），正常存盘成功后清掉。下次启动若发现草稿，顶部横幅问「恢复 / 丢弃」，**磁盘一个字节都不动**，直到你按 Ctrl+S。
  - 为什么不塞进 `config.json`：草稿是每 300ms 一次的**全量重写**，而配置里躺着窗口尺寸、主题名、lastFile。混在一起等于「写草稿失败会连带丢配置」，反过来改个侧栏宽度也要把整篇正文序列化一遍。两者生命周期不同，必须分文件。
  - 上限按**字节**判（2MB），不按字符——中文一个字 3 字节，按 `.length` 会让实际写入到上限的 3 倍。内容与上次落盘一致时跳过写盘。
- **关窗拦截**：渲染层把 `dirty` 推给主进程，关窗时若有未保存改动弹三选一（保存并关闭 / 取消 / 放弃改动）。
  - 「保存并关闭」只在真的写到盘上时才退出：`doSave()` 返回 `boolean`，为 `false` 就留在窗口里。**没保存也关掉**是这条链路上最容易犯的错——点完对话框窗口没了，内容也没了。
  - 正在写盘的那一轮 `doSave()` 返回 `false`（还没落盘），所以 `save-then-quit` 会等它写完再走一遍，而不是直接放弃。
- **单实例锁**：多开会让同一文件被两个编辑器互相覆盖。
- **上次状态**：`lastFile` 记上次打开的文件，重启自动打开；侧栏宽度也能拖拽记住（双击把手恢复 240px）。
